# Personal and group chat implementation plan

**Goal:** Personal text messages across devices and shared user-group chat using the configured Feishu Drive storage.
**Architecture:** Locally encrypted append-only messages, immutable encrypted cloud batches, deterministic IDs and deduplication. Reuse cloud vault identity and group keys. Per-user local copies permit different local passwords. Sync every joined room independently of the current workspace. No AI replies, attachments, edits, or deletion in this version.
**Tech stack:** Existing Electron IPC, sql.js, Node crypto, React/TypeScript.
**Authorization:** User requested implementation and opted for the proposed defaults; implement inline in this checkout on a feature branch.

## Constraints and review focus
- Text stays encrypted in SQLite and Feishu. Never upload local passwords or wrapped local keys.
- Personal rooms require the linked vault identity for cloud sync; local use works offline.
- Group participants must have access to the same explicit Feishu shared folder; never fall back to a private root.
- Existing invitations are local-only. Add portable, email-bound, expiring secret invitations importing the existing group key and membership; possession grants access. Feishu folder ACL is the cross-device access-control authority. Removing a local member does not revoke previously shared keys: explain this in UI/docs and require removing folder access for cloud revocation.
- Cloud files are immutable batches of at most 100 messages, under the upload size limit. Never remove remote history. List every Feishu folder page.
- Validate payloads, duplicate IDs, wrong room/vault, read-only roles, wrong password, damaged batches, account changes during async sync, and password changes.
